# 陪驾插件（escort_driving）说明文档

**插件名称**：escort-driving
**版本**：1.0.0
**业务域**：`escort`
**文档定位**：面向插件使用者和核心库扩展者，完整说明目录结构、文件功能、对象关系与使用方法。

---

## 一、插件概览

陪驾插件是 UMCP 协议栈的第一个行业插件（阶段二产出），用于验证插件化架构的可扩展性。它实现了"学员预约教练进行陪驾练习"的业务场景，覆盖任务发布、教练匹配、按时计费、信任评价全链路。

**核心定位**：
- 通过子类化核心库抽象基类实现行业语义（零核心库抽象基类修改）
- 通过组合核心库预置组件实现业务策略（`InstantMatch` + `Hourly` + `WeightedSumTrustEngine`）
- 通过 `plugin.json` 声明式配置 + `register_plugin` 钩子完成注入

**业务参数**：
- 平台抽成：20%（`FlatCommissionRule(rate=0.20)`）
- 时薪：80 元/小时（`Hourly(hourly_rate=80.0)`）
- 信任维度：3 维（teaching_ability / patience / safety_record）
- 准入规则：`hasCredential('coach_license') && trustScore >= 4.0`

## 三、核心模块详解

### 3.1 `plugin.json` — 声明式插件清单

由 `UMCPServer._apply_manifest` 解析。

| 字段 | 值 | 用途 |
|------|-----|------|
| `name` | `"escort-driving"` | 插件唯一标识 |
| `version` | `"1.0.0"` | 版本号 |
| `domain` | `"escort"` | 业务域标签 |
| `task_types` | `["escort_driving.tasks.EscortTask"]` | 任务类点路径 |
| `resource_types` | `["escort_driving.resources.CoachResource"]` | 资源类点路径 |
| `match_strategy` | `"umcp_core.layers.l3.matching.InstantMatch"` | 匹配策略类路径 |
| `trust_dimensions` | `["teaching_ability", "patience", "safety_record"]` | 信任引擎 3 维度 |
| `commission_rate` | `0.20` | 平台抽成 20% |
| `hourly_rate` | `80.0` | 时薪 80 元/小时 |
| `access_rule_expression` | `"hasCredential('coach_license') && trustScore >= 4.0"` | 准入规则表达式 |

### 3.2 `__init__.py` — 插件入口与注册钩子

#### `PLUGIN_MANIFEST`

与 `plugin.json` 内容完全一致的 Python 字典，供"模块路径方式加载"使用（即 `server.load_plugin("escort_driving")` 直接 import 此常量，无需读 JSON 文件）。

#### `register_plugin(server: UMCPServer) -> None`

插件自定义初始化钩子，按 domain 注册需要构造参数的组件：

```python
def register_plugin(server: "UMCPServer") -> None:
    domain = "escort"
    # L3 匹配策略：InstantMatch + EscortMatchScorer + CredentialFilter
    server.register_match_strategy(
        domain,
        InstantMatch(
            scorer=EscortMatchScorer(),
            filters=[CredentialFilter(required_credentials=["coach_license"])],
        ),
    )
    # L4 支付模式：Hourly + FlatCommissionRule
    server.register_payment_schema(
        domain,
        Hourly(hourly_rate=80.0, commission_rule=FlatCommissionRule(rate=0.20)),
    )
    # L5 信任引擎：WeightedSumTrustEngine（3 维）
    server.register_trust_engine(
        domain,
        WeightedSumTrustEngine(dimensions=["teaching_ability", "patience", "safety_record"]),
    )
```

**分工设计**：
- `plugin.json` 负责声明式字段（task_types / resource_types / match_strategy 类路径 / access_rule 表达式），由 `server._apply_manifest` 处理
- `register_plugin` 钩子负责需要构造参数的组件（带 scorer / filters / hourly_rate / dimensions 的实例化）

### 3.3 `tasks.py` — EscortTask（陪驾任务）

```
umcp_core.core.task.StandardTask
        ▲
        │ inherits
        │
   EscortTask
        ├─ _task_type_name = "escort"      # 供 TaskFactory 注册
        ├─ structured_fields:
        │   ├─ car_type: str               # "manual" | "automatic"，默认 "manual"
        │   ├─ required_skills: list[str]  # 默认 []
        │   └─ duration_hours: float       # 默认 1.0
        └─ custom_fields:
            └─ actual_hours: float         # 供 Hourly 支付策略读取，默认 = duration_hours
```

**构造签名**：
```python
EscortTask(
    demander_id: str,
    domain_tag: DomainTag,
    origin_lat: float,
    origin_lng: float,
    car_type: str = "manual",
    required_skills: list[str] | None = None,
    duration_hours: float = 1.0,
    **kwargs: Any,
)
```

**关键设计**：
1. 内部构造 `SpatioTemporalConstraint(origin_lat, origin_lng)` 传给父类 `StandardTask`
2. `duration_hours` 同时写入 `structured_fields`（业务字段）和 `custom_fields["actual_hours"]`（支付字段）——后者供 `Hourly` 支付策略读取；服务完成时可由调用方更新 `actual_hours` 以反映真实时长
3. `task_type()` 返回 `"escort"`，`_task_type_name` 类属性供 `TaskFactory` 注册
4. 状态转移完全继承自 `Task` 状态机（`DRAFT → PUBLISHED → MATCHING → ASSIGNED → IN_PROGRESS → COMPLETED`）

### 3.4 `resources.py` — CoachResource（教练资源）

```
umcp_core.core.resource.Resource
        ▲
        │ inherits
        │
   CoachResource
        ├─ resource_type() = "coach"
        ├─ 默认 capabilities:
        │   └─ Capability(type="certification", name="coach_license", value="A1", verified=True)
        └─ metadata:
            ├─ current_lat: float
            ├─ current_lng: float
            ├─ car_type: str               # 默认 "manual"
            ├─ coach_level: str            # 默认 "B"，可选 "A" / "B"
            ├─ skills: list[str]           # 默认 []
            └─ plate_number: str           # 默认 ""
```

**构造签名**：
```python
CoachResource(
    supplier_id: str,
    domain_tag: DomainTag,
    current_lat: float,
    current_lng: float,
    car_type: str = "manual",
    coach_level: str = "B",
    skills: list[str] | None = None,
    plate_number: str = "",
    capabilities: list[Capability] | None = None,
    **kwargs: Any,
)
```

**关键设计**：
1. 若未传入 `capabilities`，自动注入默认 `coach_license` 凭证（对应准入规则 `hasCredential('coach_license')`）
2. 显式传入 `capabilities` 时**覆盖默认**（测试 `test_custom_capabilities_override_default` 验证）
3. 业务字段存入 `metadata`，与核心库 `Resource` 的通用字段（`resource_id` / `status` / `capabilities`）分离

### 3.5 `scoring.py` — EscortMatchScorer（陪驾匹配评分器）

```
EscortMatchScorer
    ├─ 内部组合 SkillMatchScorer（来自 umcp_core.layers.l3）
    └─ __call__(task: Task, resource: Resource) -> float
```

**评分算法**（按顺序）：

1. **硬性约束（车型匹配）**：
   - 从 `task.structured_fields["car_type"]` 与 `resource.metadata["car_type"]` 取值
   - 不匹配直接返回 `-1.0`（`CAR_TYPE_MISMATCH_SCORE`），降序排序时排到最后

2. **技能匹配分**：
   - 调用 `self._skill_scorer(task, resource)`
   - 返回 `task.required_skills` 与 `resource.skills` 的交集技能数

3. **教练等级加权**：
   - 从 `resource.metadata["coach_level"]` 取值（默认 `"B"`）
   - 查 `COACH_LEVEL_WEIGHT` 映射：`{"A": 1.0, "B": 0.0}`

4. **综合评分** = 技能匹配分 + 等级加权

**模块常量**：
```python
COACH_LEVEL_WEIGHT: dict[str, float] = {"A": 1.0, "B": 0.0}
CAR_TYPE_MISMATCH_SCORE: float = -1.0
```

**评分方向**：降序优先（高分优先，与 `InstantMatch` 的 `reverse=True` 一致）

**设计说明**：教练等级加权是陪驾特有逻辑，其他行业（家教、家政）有不同的等级体系，无法通用，因此放在插件而非核心库。

## 四、对象关系总览

### 4.1 类继承与组合关系

```
umcp_core.core.task.Task (ABC)
    └── umcp_core.core.task.StandardTask
            └── escort_driving.tasks.EscortTask
                    ├─ structured_fields: {car_type, required_skills, duration_hours}
                    └─ custom_fields: {actual_hours}

umcp_core.core.resource.Resource (ABC)
    └── escort_driving.resources.CoachResource
            ├─ metadata: {current_lat, current_lng, car_type, coach_level, skills, plate_number}
            └─ default capabilities: [Capability(coach_license)]

umcp_core.layers.l3.SkillMatchScorer  ◄── 组合 ──┐
                                                  │
                                          EscortMatchScorer
                                                  │ __call__(task, resource) -> float
                                                  │ 算法 = (car_type 检查) → (skill_score) + (coach_level 加权)
```

### 4.2 与核心库 L3/L4/L5 层的对接

| 核心层 | 核心组件 | 插件中的对接点 |
|--------|---------|---------------|
| L3 匹配 | `InstantMatch` / `CredentialFilter` / `SkillMatchScorer` | `register_plugin` 实例化 `InstantMatch`；`EscortMatchScorer` 内部组合 `SkillMatchScorer`；filters 要求 `coach_license` |
| L4 支付 | `Hourly` / `FlatCommissionRule` | `register_plugin` 实例化 `Hourly(hourly_rate=80)` + `FlatCommissionRule(rate=0.20)`；`EscortTask.custom_fields["actual_hours"]` 供 `Hourly` 读取 |
| L5 信任 | `WeightedSumTrustEngine` / `Evaluation` | `register_plugin` 实例化引擎（3 维度）；准入规则 `trustScore >= 4.0` 由 `RuleEngine.check_access` 评估 |

### 4.3 完整业务流程

```
1. 学员发布陪驾任务（EscortTask）
   ├─ car_type="manual", required_skills=["night_driving"], duration_hours=2.0
   └─ task.publish() → status=MATCHING

2. UMCPServer 按域路由到 escort 域 InstantMatch
   ├─ CredentialFilter 过滤无 coach_license 的教练
   └─ EscortMatchScorer 评分：
       ├─ 车型不匹配 → -1.0（排除）
       └─ score = 交集技能数 + coach_level 加权（A=+1.0, B=+0.0）

3. 匹配成功 → assign_to → start_execution

4. 服务完成 → complete()
   └─ custom_fields["actual_hours"] 可由调用方更新为真实时长

5. Hourly 支付策略计算
   ├─ total_amount = actual_hours × 80 元/小时
   ├─ commission = total_amount × 0.20
   └─ supplier_amount = total_amount - commission

6. 信任评价（Evaluation）
   └─ WeightedSumTrustEngine.record_evaluation(ratings={teaching_ability: 5.0, ...})
       → 更新 TrustProfile，影响下次准入
```

## 六、使用方法

### 6.1 加载插件

```python
from umcp_core.server import UMCPServer

server = UMCPServer()
server.use_in_memory_repositories()
server.load_plugin("plugins/escort_driving/plugin.json")
# 或通过模块名加载
# server.load_plugin("escort_driving")
server.start()
```

### 6.2 创建陪驾任务

```python
from umcp_core.core.domain import DomainTag
from escort_driving.tasks import EscortTask

task = EscortTask(
    demander_id="student_001",
    domain_tag=DomainTag.of("escort"),
    origin_lat=39.9042,
    origin_lng=116.4074,
    car_type="manual",
    required_skills=["night_driving", "highway"],
    duration_hours=2.0,
)
task.publish()  # DRAFT → MATCHING
```

### 6.3 注册教练资源

```python
from umcp_core.core.domain import DomainTag
from escort_driving.resources import CoachResource

coach = CoachResource(
    supplier_id="coach_001",
    domain_tag=DomainTag.of("escort"),
    current_lat=39.9050,
    current_lng=116.4080,
    car_type="manual",
    coach_level="A",
    skills=["night_driving", "highway", "parking"],
    plate_number="京A12345",
)
coach.register()  # OFFLINE → IDLE
server.resource_repo.save(coach)
```

### 6.4 匹配与支付

```python
from umcp_core.core.deal import Deal

# 匹配
strategy = server.match_strategy_for("escort")
candidates = server.resource_repo.find_available(task.domain_tag)
result = strategy.execute(task, candidates)

# 创建交易
deal = Deal(
    task_id=task.task_id,
    resource_id=result.selected_resource_id,
    demander_id=task.demander_id,
    supplier_id="coach_001",
    final_amount=160.0,  # 2 小时 × 80 元
)
deal.activate()

# 支付
payment = server.payment_schema_for("escort").calculate(task, deal)
# payment.total_amount = 160.0
# payment.commission = 32.0
# payment.supplier_amount = 128.0
```

## 七、设计要点总结

1. **零核心库抽象基类修改**：所有扩展通过子类化 `StandardTask` / `Resource` 和组合 `SkillMatchScorer` 实现
2. **声明式 + 命令式双注入**：`plugin.json` 处理声明式字段，`register_plugin` 钩子处理需要构造参数的组件
3. **评分器组合复用**：`EscortMatchScorer` 内部组合核心库 `SkillMatchScorer`，行业特有逻辑（车型匹配、教练等级加权）在插件内实现
4. **`actual_hours` 双写设计**：`duration_hours` 同时写入 `structured_fields`（业务字段）和 `custom_fields["actual_hours"]`（支付字段），支持服务完成后更新真实时长
5. **默认凭证自动注入**：`CoachResource` 构造时自动注入 `coach_license`，满足准入规则，显式传入 `capabilities` 时覆盖
6. **`PLUGIN_MANIFEST` 与 `plugin.json` 冗余设计**：双份相同配置，前者支持模块路径加载，后者支持 JSON 文件加载
