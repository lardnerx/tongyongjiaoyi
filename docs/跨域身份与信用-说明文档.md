# 跨域身份与信用（阶段四 B）说明文档

**版本**：1.0.0
**适用范围**：UMCP-Core 阶段四 B 产出（信任分按 domain 隔离 + 跨 domain 聚合视图）
**文档定位**：面向核心库使用者和插件开发者，完整说明跨域信任隔离与聚合的设计、数据流、使用方法与测试覆盖。

---

## 一、概述

### 1.1 背景与问题

UMCP 协议栈支持按 `domain` 加载多插件并存（ride / group_buying / design 等）。每个插件会通过 `register_trust_engine(domain, engine)` 注入自己的 `TrustEngine`，记录该 domain 内的用户评价与信誉画像。

阶段四 A 之前，`access_rule` 中的 `trustScore` 字段是从 `user.metadata['trust_score']` 读取的全局值，这意味着：

- **问题 1：跨 domain 评分串扰**。同一用户在打车域（ride）的差评会拉低他在集采域（group_buying）的 trust_score，导致他在集采域被准入规则拦截。这对多业务运营是不可接受的——一个糟糕的乘客不应因此无法参与集采招标。
- **问题 2：缺乏跨 domain 聚合视图**。某些场景（如平台级 KYC、风控总览、跨域推荐）需要查看用户的"综合信誉"，而阶段四 A 之前没有统一的聚合入口。

### 1.2 核心设计

阶段四 B 通过三个改动同时解决上述两个问题，关键决策是**仅隔离 `trust_score`，`credentials` 保持共享**：

1. **信任分按 domain 隔离**：在 `RuleEngine` 中维护 `domain → TrustEngine` 映射，`RuleContext.trust_score` 通过 `task.domain_tag` 路由到对应 domain 的 `TrustEngine` 取值。这样打车评价只影响打车域的 trust_score，不影响集采域。
2. **`credentials` 保持共享**：身份凭证（如 `business_license`、`driver_license`）仍是用户级别的属性，跨 domain 通用。一个用户拿到营业执照后，在所有 domain 都能出示。这避免了"同一凭证需在每个 domain 重复颁发"的冗余。
3. **`TrustAggregator` 抽象 + 默认 `MeanTrustAggregator`**：定义跨 domain 聚合策略接口，默认实现取算术平均。`UMCPServer.aggregate_trust_score(user_id)` 提供跨 domain 聚合视图入口。行业应用可通过 `set_trust_aggregator()` 注入自定义策略（如交易量加权、取最低分等）。

### 1.3 设计取舍

| 设计选项 | 是否采纳 | 理由 |
|---------|---------|------|
| 完全隔离 credentials + trust_score | 否 | 凭证是用户级身份属性，跨 domain 重复颁发不合理 |
| 仅隔离 trust_score，credentials 共享 | **是** | 信任分反映 domain 内行为，凭证反映身份资质，二者语义不同 |
| 在 TrustEngine 内部按 domain 分桶存储 | 否 | 改动 WeightedSumTrustEngine 内部结构，破坏单一 engine 单一 profile 的语义 |
| 每个 domain 一个独立 TrustEngine 实例 | **是** | 复用 `WeightedSumTrustEngine._profiles` 存储，零侵入 |
| 硬编码聚合算法（算术平均） | 否 | 不同行业有不同聚合需求（最低分、加权平均等） |
| `TrustAggregator` 抽象 + 默认实现 | **是** | 通过依赖注入支持行业定制，符合核心库"抽象基类 + 默认实现"的风格 |

## 三、核心设计

### 3.1 信任分 domain 隔离

#### 3.1.1 `RuleEngine._domain_trust_engines`：domain→engine 映射

`RuleEngine` 在 `__init__` 中新增字段 ` _domain_trust_engines: dict[str, TrustEngine]`（见 `governance.py:199`），按 domain 存储 TrustEngine 引用。`register_trust_engine(domain, engine)` 方法（`governance.py:214-219`）负责注册，domain 统一小写化以与 `DomainTag.of(...).value` 保持一致：

```python
def register_trust_engine(self, domain: str, engine: TrustEngine) -> None:
    """注册 domain 对应的 TrustEngine，供 RuleContext.trust_score 路由。

    domain 统一小写化存储，与 DomainTag.of(...).value 保持一致。
    """
    self._domain_trust_engines[domain.lower()] = engine
```

#### 3.1.2 `RuleContext.trust_score`：按 `task.domain_tag` 路由

`RuleContext` 新增可选字段 `trust_engine_for_domain: Callable[[str], TrustEngine | None]`（`governance.py:133`），由调用方注入"domain → engine"查询回调。`trust_score` 属性（`governance.py:140-152`）按以下优先级取值：

1. 若 `trust_engine_for_domain` 已注入且能查到 `task.domain_tag.value` 对应的 engine：返回 `engine.evaluate(user_id).overall_score`
2. 否则回退到 `user.metadata['trust_score']`（向后兼容阶段四 A 之前的行为）

```python
@property
def trust_score(self) -> float:
    if self.trust_engine_for_domain is not None:
        engine = self.trust_engine_for_domain(self.task.domain_tag.value)
        if engine is not None:
            return engine.evaluate(self.user.user_id).overall_score
    return float(self.user.metadata.get("trust_score", 0.0))
```

**回退策略的意义**：
- 向后兼容：未注册 domain 的 task 仍走 metadata 路径，老代码不需改动
- 容错：domain 未注册 engine 时不会抛异常，而是退化为 metadata 取值

#### 3.1.3 `ExpressionAccessRule.bind_trust_engine_lookup()`：注入点

`ExpressionAccessRule` 新增 `_trust_engine_lookup` 字段（`governance.py:37`）和 `bind_trust_engine_lookup()` 方法（`governance.py:39-47`）。该方法**幂等**——重复调用不会覆盖已绑定的 lookup：

```python
def bind_trust_engine_lookup(
    self, lookup: Callable[[str], TrustEngine | None]
) -> None:
    """由 RuleEngine 在 check_access 前注入 domain→engine 路由能力。

    幂等：重复调用不会覆盖已绑定的 lookup。
    """
    if self._trust_engine_lookup is None:
        self._trust_engine_lookup = lookup
```

`check()` 方法（`governance.py:49-55`）在构造 `RuleContext` 时把 `_trust_engine_lookup` 透传给 `trust_engine_for_domain` 字段，使表达式求值器能通过 `ctx.trust_score` 走 domain 路由：

```python
def check(self, user: User, task: Task) -> bool:
    ctx = RuleContext(
        user=user,
        task=task,
        trust_engine_for_domain=self._trust_engine_lookup,
    )
    return _evaluate_expression(self.expression, ctx)
```

### 3.2 TrustAggregator 跨域聚合

#### 3.2.1 `TrustAggregator` 抽象基类

定义在 `trust.py:170-192`，只有一个抽象方法 `aggregate(user_id, engines) -> float`：

```python
class TrustAggregator(ABC):
    """跨 domain 信任聚合策略接口。

    用于跨 domain 聚合同一用户的 trust_score。
    默认实现为 MeanTrustAggregator（算术平均），行业应用可注入
    自定义实现（如交易量加权平均、取最低分等）。
    """

    @abstractmethod
    def aggregate(
        self,
        user_id: str,
        engines: dict[str, TrustEngine],
    ) -> float:
        """跨 domain 聚合 trust_score。

        Args:
            user_id: 用户 ID
            engines: domain → TrustEngine 映射（只含已注册的 domain）

        Returns:
            聚合后的 trust_score（0.0-5.0）
        """
```

#### 3.2.2 `MeanTrustAggregator` 默认实现

`trust.py:195-217`，对每个 domain 的 `TrustEngine.evaluate(user_id).overall_score` 取算术平均：

```python
class MeanTrustAggregator(TrustAggregator):
    """算术平均聚合策略（默认实现）。

    注意：未在某 engine 中留过评价记录的用户，evaluate() 会返回
    overall_score=0.0 的空 profile，仍纳入平均（这通常是期望行为：
    新用户从 0 分起步）。
    """

    def aggregate(
        self,
        user_id: str,
        engines: dict[str, TrustEngine],
    ) -> float:
        if not engines:
            return 0.0
        scores = [
            engine.evaluate(user_id).overall_score
            for engine in engines.values()
        ]
        return sum(scores) / len(scores)
```

**边界处理**：
- `engines` 为空字典时返回 `0.0`
- 用户在某 engine 没有评价记录时，`WeightedSumTrustEngine.evaluate()` 会返回 `overall_score=0.0` 的空 profile，仍纳入平均

### 3.3 RuleEngine 改造

`RuleEngine` 改造涉及三处：

#### 3.3.1 新增 `_domain_trust_engines` 字段

在 `__init__`（`governance.py:195-201`）中新增：

```python
self._domain_trust_engines: dict[str, TrustEngine] = {}
```

#### 3.3.2 `register_trust_engine(domain, engine)` 方法

见 3.1.1，将 domain 小写化后存入 `_domain_trust_engines`。

#### 3.3.3 `check_access()` 注入路由能力

`check_access()` 方法（`governance.py:227-242`）在调用 `rule.check()` 之前，向所有未绑定的 `ExpressionAccessRule` 注入 domain→engine 路由回调：

```python
def check_access(self, user: User, task: Task) -> bool:
    domain = task.domain_tag.value
    rules = self._domain_access_rules.get(domain, []) + self._access_rules
    # 注入 domain→engine 路由能力到 ExpressionAccessRule（仅一次，幂等）
    for rule in rules:
        if isinstance(rule, ExpressionAccessRule) and rule._trust_engine_lookup is None:
            rule.bind_trust_engine_lookup(
                lambda d: self._domain_trust_engines.get(d)
            )
    return all(rule.check(user, task) for rule in rules)
```

**关键点**：
- 注入的 lookup 是 `lambda d: self._domain_trust_engines.get(d)`，闭包捕获 `self`，能动态反映后续注册的 engine
- 幂等性由 `bind_trust_engine_lookup()` 自身保证：仅当 `rule._trust_engine_lookup is None` 时才注入
- `check_access` 同时检查 `rule._trust_engine_lookup is None`，避免对已绑定的 rule 重复调用 `bind_trust_engine_lookup`

### 3.4 UMCPServer 改造

`UMCPServer` 改造涉及四处：

#### 3.4.1 新增 `_trust_aggregator` 字段

在 `__init__`（`server.py:102`）中新增，默认为 `MeanTrustAggregator()`：

```python
# 跨 domain 信任聚合器（默认算术平均）
self._trust_aggregator: TrustAggregator = MeanTrustAggregator()
```

#### 3.4.2 `register_trust_engine(domain, engine)` 同步到 RuleEngine

`server.py:185-197`，除了更新 `_trust_engines[domain]` 和单值属性 `trust_engine`，**还同步注册到 `rule_engine`**，使 access_rule 的 `trustScore` 能按 domain 路由：

```python
def register_trust_engine(self, domain: str, engine: TrustEngine) -> None:
    """按 domain 注册信任引擎。

    同时：
    - 更新单值属性 self.trust_engine（兜底）
    - 注册到 self._trust_engines[domain]
    - 同步到 self.rule_engine（供 RuleContext.trust_score 路由）
    """
    key = domain.lower()
    self._trust_engines[key] = engine
    self.trust_engine = engine
    # 同步到 RuleEngine，使 access_rule 的 trustScore 能按 domain 路由
    self.rule_engine.register_trust_engine(key, engine)
```

#### 3.4.3 `set_trust_aggregator(aggregator)` 注入聚合策略

`server.py:214-216`，简单赋值，支持运行时替换：

```python
def set_trust_aggregator(self, aggregator: TrustAggregator) -> None:
    """注入自定义信任聚合策略（默认 MeanTrustAggregator）。"""
    self._trust_aggregator = aggregator
```

#### 3.4.4 `aggregate_trust_score(user_id)` 跨 domain 聚合

`server.py:218-224`，委托给 `_trust_aggregator`，传入 `self._trust_engines`：

```python
def aggregate_trust_score(self, user_id: str) -> float:
    """跨 domain 聚合 trust_score。

    返回所有已注册 domain 的 TrustEngine.evaluate(user_id).overall_score
    的聚合结果（默认算术平均，可通过 set_trust_aggregator 自定义）。
    """
    return self._trust_aggregator.aggregate(user_id, self._trust_engines)
```

## 四、数据流

### 4.1 单 domain trust_score 查询流程（access_rule 求值）

```
用户调用 server.rule_engine.check_access(user, task)
    │
    ├─ 1. 取 domain = task.domain_tag.value（如 "ride"）
    ├─ 2. 取 rules = _domain_access_rules[domain] + _access_rules
    │
    ├─ 3. 对每个 ExpressionAccessRule（仅 _trust_engine_lookup is None 的）：
    │       └─ rule.bind_trust_engine_lookup(
    │              lambda d: self._domain_trust_engines.get(d)
    │          )
    │
    └─ 4. 对每个 rule 调用 rule.check(user, task)
            │
            └─ ExpressionAccessRule.check(user, task)
                    │
                    ├─ 构造 RuleContext(
                    │       user=user,
                    │       task=task,
                    │       trust_engine_for_domain=self._trust_engine_lookup
                    │   )
                    │
                    └─ _evaluate_expression(expression, ctx)
                            │
                            ├─ 遇到 trustScore → 读 ctx.trust_score
                            │       │
                            │       ├─ trust_engine_for_domain 已注入？
                            │       │   ├─ 是：engine = lookup(task.domain_tag.value)
                            │       │   │       ├─ engine 非 None → engine.evaluate(user.user_id).overall_score
                            │       │   │       └─ engine 为 None → 回退 metadata
                            │       │   └─ 否：回退 user.metadata['trust_score']
                            │       │
                            │       └─ 返回 float 分数
                            │
                            └─ 替换 trustScore 为分数后 eval 表达式
```

**示例**：用户 `u1` 在 ride 域评分 5.0、gb 域评分 2.0，规则 `trustScore >= 3.0`
- ride task：`lookup("ride")` → ride_te → `evaluate("u1").overall_score = 5.0` → `5.0 >= 3.0` → True
- gb task：`lookup("group_buying")` → gb_te → `evaluate("u1").overall_score = 2.0` → `2.0 >= 3.0` → False

### 4.2 跨 domain 聚合流程

```
用户调用 server.aggregate_trust_score(user_id)
    │
    └─ self._trust_aggregator.aggregate(user_id, self._trust_engines)
            │
            ├─ MeanTrustAggregator.aggregate(user_id, engines)
            │       │
            │       ├─ engines 为空 → 返回 0.0
            │       │
            │       └─ 对每个 (domain, engine) in engines：
            │              └─ score = engine.evaluate(user_id).overall_score
            │
            └─ 返回 sum(scores) / len(scores)
```

**示例**：用户 `u1` 在 ride 域 4.8、gb 域 3.5，默认聚合
- `engines = {"ride": ride_te, "group_buying": gb_te}`
- `scores = [4.8, 3.5]`
- 返回 `(4.8 + 3.5) / 2 = 4.15`

### 4.3 注册同步流程

```
插件加载或手动调用 server.register_trust_engine("ride", ride_te)
    │
    ├─ self._trust_engines["ride"] = ride_te
    ├─ self.trust_engine = ride_te               # 单值属性兜底
    └─ self.rule_engine.register_trust_engine("ride", ride_te)
            │
            └─ self._domain_trust_engines["ride"] = ride_te
                    │
                    └─ 后续 check_access 注入的 lookup 闭包能动态查到该 engine
```

## 五、使用方法

### 5.1 注册多 domain TrustEngine

```python
from umcp_core.server import UMCPServer
from umcp_core.layers.l5 import WeightedSumTrustEngine

server = UMCPServer()
server.use_in_memory_repositories()

# 为 ride 域注册 1 维信任引擎
ride_te = WeightedSumTrustEngine(dimensions=["overall"])
server.register_trust_engine("ride", ride_te)

# 为 group_buying 域注册 4 维信任引擎（维度可不同）
gb_te = WeightedSumTrustEngine(
    dimensions=["delivery", "quality", "service", "cost_performance"]
)
server.register_trust_engine("group_buying", gb_te)

# 此时：
# - server._trust_engines = {"ride": ride_te, "group_buying": gb_te}
# - server.rule_engine._domain_trust_engines 同步持有相同映射
# - server.trust_engine 兜底为最后注册的 gb_te
```

### 5.2 记录评价并查询单 domain trust_score

```python
from umcp_core.layers.l5.trust import Evaluation

# ride 域：用户 u1 收到 5.0 评价
ride_te.record_evaluation(
    Evaluation(
        evaluator_id="e1",
        evaluatee_id="u1",
        task_id="t1",
        ratings={"overall": 5.0},
    )
)

# group_buying 域：用户 u1 收到 4 维评价
gb_te.record_evaluation(
    Evaluation(
        evaluator_id="e2",
        evaluatee_id="u1",
        task_id="t2",
        ratings={"delivery": 4.5, "quality": 4.0, "service": 5.0, "cost_performance": 4.0},
    )
)

# 直接查询单 domain 的 trust_score
ride_score = ride_te.evaluate("u1").overall_score          # = 5.0
gb_score = gb_te.evaluate("u1").overall_score               # = 4.375（4 维平均）

# 通过 server 查询单 domain
from umcp_core.core.domain import DomainTag
ride_engine = server.trust_engine_for("ride")               # 回退到 trust_engine
ride_engine.evaluate("u1").overall_score                    # = 5.0
```

### 5.3 通过 access_rule 验证 domain 隔离

```python
from umcp_core.layers.l7 import ExpressionAccessRule
from umcp_core.core.base import User
from umcp_core.core.domain import Credential, DomainTag
from umcp_core.core.task import CustomTask
```

### 5.5 自定义聚合策略

```python
from umcp_core.layers.l5 import TrustAggregator

class MinTrustAggregator(TrustAggregator):
    """取最低分聚合策略：跨域最差表现决定总信誉。

    适用场景：风控严苛的场景，如金融、医疗。
    任一 domain 的低分都会拉低综合信誉。
    """

    def aggregate(self, user_id: str, engines) -> float:
        if not engines:
            return 0.0
        return min(e.evaluate(user_id).overall_score for e in engines.values())


class WeightedTrustAggregator(TrustAggregator):
    """按 domain 交易量加权平均。

    适用场景：交易量大的 domain 应占更高权重。
    """

    def __init__(self, domain_weights: dict[str, float]) -> None:
        self.domain_weights = domain_weights

    def aggregate(self, user_id: str, engines) -> float:
        if not engines:
            return 0.0
        total_weight = 0.0
        weighted_sum = 0.0
        for domain, engine in engines.items():
            w = self.domain_weights.get(domain, 1.0)
            weighted_sum += engine.evaluate(user_id).overall_score * w
            total_weight += w
        return weighted_sum / total_weight if total_weight > 0 else 0.0


# 注入取最低分策略
server.set_trust_aggregator(MinTrustAggregator())
assert server.aggregate_trust_score("u1") == min(5.0, 4.375)  # = 4.375

# 注入加权策略
server.set_trust_aggregator(WeightedTrustAggregator(
    domain_weights={"ride": 1.0, "group_buying": 3.0}  # 集采权重更高
))
```

### 5.6 通过插件 manifest 自动注册

`UMCPServer._apply_manifest()`（`server.py:286-342`）在解析 `plugin.json` 时，若 manifest 含 `trust_engine` 字段且 `domain` 非空，会自动调用 `register_trust_engine(domain, instance)`，无需手动调用：

```json
{
  "name": "ride-hailing",
  "domain": "ride",
  "trust_engine": "umcp_core.layers.l5.WeightedSumTrustEngine",
  "access_rule_expression": "hasCredential('driver_license') && trustScore >= 4.0"
}
```

加载后：
- `server._trust_engines["ride"]` 持有 engine
- `server.rule_engine._domain_trust_engines["ride"]` 同步持有
- `access_rule_expression` 自动按 `domain="ride"` 注册到 `rule_engine._domain_access_rules["ride"]`
- `check_access` 时 `trustScore` 自动路由到 ride 域 engine

## 七、设计要点总结

1. **最小化隔离范围**：仅隔离 `trust_score`，`credentials` 保持共享。这避免了"同一凭证需在每个 domain 重复颁发"的冗余，同时解决了跨域评分串扰问题。

2. **复用既有存储**：每个 domain 一个独立 `WeightedSumTrustEngine` 实例，复用其 `_profiles: dict[str, TrustProfile]` 存储，零侵入。无需为跨域隔离新增数据结构。

3. **抽象 + 默认实现**：`TrustAggregator` 抽象基类 + `MeanTrustAggregator` 默认实现，符合核心库"抽象基类 + 默认实现 + 依赖注入"的一贯风格。行业应用可通过 `set_trust_aggregator()` 注入交易量加权、取最低分等定制策略。

4. **向后兼容**：`RuleContext.trust_engine_for_domain` 是可选字段，未注入时回退到 `user.metadata['trust_score']`。阶段四 A 之前的代码无需改动。

5. **幂等注入**：`bind_trust_engine_lookup()` 与 `check_access()` 的注入逻辑都是幂等的——重复调用不会覆盖已绑定的 lookup。这避免了多线程或多次 check_access 调用时的竞态问题。

6. **闭包动态查询**：`check_access` 注入的 lookup 是 `lambda d: self._domain_trust_engines.get(d)`，闭包捕获 `self`，能动态反映后续注册的 engine。即使 lookup 在 engine 注册前已注入，后续注册的 engine 也能被查到。

7. **domain 统一小写化**：`register_trust_engine` 在 `RuleEngine` 与 `UMCPServer` 中都做 `domain.lower()` 处理，与 `DomainTag.of(...).value` 的语义保持一致，避免大小写敏感导致的路由 miss。

8. **零核心库抽象基类修改**：所有改动通过新增字段、新增方法、新增子类实现，不修改 `TrustEngine` / `AccessRule` / `User` 等抽象基类的接口契约。
