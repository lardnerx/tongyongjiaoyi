二、开发架构对比

2.1 规划版（方案 A'：混合共享）

三层共享架构：共享基础设施层（认证 / 支付 / LBS / 通知 / 存储 / 规则）→ 共享领域层（umcp-core）→ 业务层（escort / ride / group 按 domain 隔离）；前端 Next.js 14 + shadcn/ui + Zustand + React Query + 高德地图；数据库核心表复用 + 业务扩展表 + 共享基础设施表，PostGIS 空间索引。

2.2 实际版

核心库
  • L1-L7 七层协议栈完整落地
  • EventBus 事件总线 + 任务/交易双状态机
  • 6 种支付模式抽象
共享层
  • payment：base / wechat / mock
  • notification：WS / 短信 / 模板 / 中心
  • rules / storage / lbs 五模块齐全
插件
  • escort_driving：实际运行
  • ride_hailing：代码+测试完整
  • group_buying：代码+测试完整（未接路由）
Web 前端
  • 身份层：login / register / reset-password
  • 学员端：实时单 / 预约单 / 订单 / 支付
  • 教练端：接单大厅 / 订单
  • 好友 friends、运营 admin/rules

2.3 差异

规划的"多业务路由分区"目前仅 escort 真正跑通；教练列表/日程管理、admin 的 dashboard/教练审核/争议处理、平台级运营页（users/stats）尚未建页面；高德地图仅为前端组件，后端 LBS 为内存实现（无 PostGIS）。
