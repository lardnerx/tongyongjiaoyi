# 集采插件（group_buying）说明文档

**插件名称**：group-buying
**版本**：1.0.0
**业务域**：`group_buying`
**文档定位**：面向插件使用者和核心库扩展者，完整说明目录结构、文件功能、对象关系与使用方法。

---

## 一、插件概览

集采插件是 UMCP 协议栈的第二个行业插件（阶段三产出，方案 B），实现了"多采购需求聚合 → 集采招标 → 供应商投标 → 分期付款 → 履约评价"的完整业务闭环。它验证了核心库 `PackageTask`（混合任务）抽象、`Bidding` 匹配策略、`InstallmentPayment` 分期支付模式的可扩展性。

**核心定位**：
- 通过子类化 `PackageTask` 实现 `TenderTask`（集采招标任务），支持商品 + 服务双子任务
- 通过子类化 `CustomTask` 实现 `BuyerTask`（采购需求意向），作为聚合原料
- 通过 `BrokerAgent` 虚拟中间人实现需求聚合（阈值=3）
- 通过 `ReverseAuction` + `TenderBidScorer` 实现多维报价评分
- 通过 `InstallmentPayment` 实现 30% 订金 + 70% 尾款分期支付

**业务参数**：
- 平台抽成：5%（`FlatCommissionRule(rate=0.05)`）
- 订金比例：30%（`deposit_ratio=0.3`）
- 信任维度：4 维（delivery / quality / service / cost_performance）
- 聚合阈值：3（`BrokerAgent.aggregation_threshold=3`）
- 准入规则：`hasCredential('business_license') && trustScore >= 3.0`

### 3.2 `__init__.py` — 插件入口与注册钩子

#### `PLUGIN_MANIFEST`

与 `plugin.json` 内容完全一致的 Python 字典，供模块路径方式加载。

#### `register_plugin(server: UMCPServer) -> None`

```python
def register_plugin(server: "UMCPServer") -> None:
    domain = "group_buying"
    # L3 匹配策略：ReverseAuction + TenderBidScorer + CredentialFilter
    server.register_match_strategy(
        domain,
        ReverseAuction(
            scorer=TenderBidScorer(),
            filters=[CredentialFilter(required_credentials=["business_license"])],
        ),
    )
    # L4 支付模式：InstallmentPayment + FlatCommissionRule
    server.register_payment_schema(
        domain,
        InstallmentPayment(deposit_ratio=0.3, commission_rule=FlatCommissionRule(rate=0.05)),
    )
    # L5 信任引擎：WeightedSumTrustEngine（4 维）
    server.register_trust_engine(
        domain,
        WeightedSumTrustEngine(dimensions=["delivery", "quality", "service", "cost_performance"]),
    )
```

### 3.3 `tasks.py` — BuyerTask + TenderTask

#### BuyerTask（采购需求意向）

```
umcp_core.core.task.CustomTask
        ▲
        │ inherits
        │
   BuyerTask
        ├─ _task_type_name = "buyer"
        ├─ 继承自 CustomTask：budget_min, budget_max, proposal_requirements, proposals
        └─ custom_fields:
            ├─ category: str           # 采购品类（如 "空调"、"保洁"）
            ├─ quantity: int           # 采购数量
            └─ spec_requirements: list[str]  # 默认 []
```

**构造签名**：
```python
BuyerTask(
    demander_id: str,
    domain_tag: DomainTag,
    category: str,
    quantity: int,
    budget_max: float,
    spec_requirements: list[str] | None = None,
    **kwargs: Any,
)
```

**关键设计**：
- 继承 `CustomTask`（非 `StandardTask`），携带预算上限 `budget_max`
- `category` 用于 `BrokerAgent` 按品类分桶聚合
- 作为聚合原料，由 `BrokerAgent.submit_buyer_task()` 提交到缓冲池

#### TenderTask（集采招标任务）

```
umcp_core.core.task.PackageTask
        ▲
        │ inherits
        │
   TenderTask
        ├─ _task_type_name = "tender"
        ├─ custom_fields:
        │   ├─ category: str
        │   ├─ total_quantity: int
        │   ├─ target_unit_price: float
        │   └─ buyer_task_ids: list[str]     # 聚合的 BuyerTask ID 列表
        │
        ├─ standard_sub_tasks: list[StandardTask]  # 商品子任务（继承自 PackageTask）
        │   └─ custom_fields: {sku="AGG-{category}", quantity=total_quantity}
        │
        ├─ custom_sub_task: CustomTask | None      # 服务子任务（继承自 PackageTask）
        │   └─ proposal_requirements=["含配送", "含安装"]
        │
        └─ 重写 complete()：前置校验所有子任务 COMPLETED
```

**构造签名**：
```python
TenderTask(
    demander_id: str,
    domain_tag: DomainTag,
    category: str,
    total_quantity: int,
    target_unit_price: float,
    buyer_task_ids: list[str],
    **kwargs: Any,
)
```

**重写 `complete()` 的前置校验**：
```python
def complete(self) -> None:
    for sub in self.standard_sub_tasks:
        if sub.status != TaskStatus.COMPLETED:
            raise RuntimeError(f"子任务 {sub.task_id} 未完成")
    if self.custom_sub_task and self.custom_sub_task.status != TaskStatus.COMPLETED:
        raise RuntimeError("服务子任务未完成")
    super().complete()
```

**子任务结构**（由 `BrokerAgent` 创建）：
- 商品子任务 `StandardTask`：`sku="AGG-{category}"`、`quantity=total_quantity`
- 服务子任务 `CustomTask`：`proposal_requirements=["含配送", "含安装"]`

**状态转移**：继承 `Task` 状态机，完整链路 `DRAFT → publish() → MATCHING → assign_to() → ASSIGNED → start_execution() → IN_PROGRESS → complete() → COMPLETED`

### 3.4 `resources.py` — SupplierResource（供应商资源）

```
umcp_core.core.resource.Resource
        ▲
        │ inherits
        │
   SupplierResource
        ├─ resource_type() = "supplier"
        ├─ 默认 capabilities:
        │   └─ Capability(type="certification", name="business_license", value="registered", verified=True)
        └─ metadata:
            ├─ supplier_name: str
            ├─ product_sku: str
            ├─ service_capability: list[str]    # 默认 []
            └─ trust_score: float               # 默认 3.0
```

**构造签名**：
```python
SupplierResource(
    supplier_id: str,
    domain_tag: DomainTag,
    supplier_name: str,
    product_sku: str,
    service_capability: list[str] | None = None,
    trust_score: float = 3.0,
    capabilities: list[Capability] | None = None,
    **kwargs: Any,
)
```

**关键设计**：
1. 默认注入 `business_license` 凭证，满足准入规则 `hasCredential('business_license')`
2. 显式传入 `capabilities` 时覆盖默认
3. `service_capability` 用于 `TenderBidScorer` 的服务能力匹配（如 `["含配送", "含安装"]`）
4. `trust_score` 默认 3.0，满足准入门槛 `trustScore >= 3.0`

### 3.5 `scoring.py` — TenderBidScorer（集采报价评分器）

```
TenderBidScorer
    ├─ 内部组合 CompositeBidScorer（来自 umcp_core.layers.l3）
    └─ __call__(task: Task, resource: Resource) -> float
```

**评分算法**（三步）：

1. **资质硬约束**：
   - `resource.has_capability("business_license")` 为 False → 返回 `-1.0`（`MISSING_REQUIREMENT_SCORE`）

2. **服务能力匹配**：
   - 取 `task.custom_fields.get("required_service_tags")`（动态优先）或 `self.required_service_tags`（静态兜底）
   - 若非空，要求 `set(required_tags) ⊆ set(resource.metadata["service_capability"])`
   - 不满足返回 `-1.0`

3. **通用报价评分**：
   - 委托 `self._composite_scorer(task, resource)` 返回综合分

**底层 `CompositeBidScorer`（核心库预置，三维度加权）**：

| 维度 | 权重 | 数据来源 | 归一化公式 |
|------|------|---------|-----------|
| 价格 | 0.5 | `resource.metadata["bid"]["price"]` | `(price_max - price) / (price_max - price_min)` |
| 交期 | 0.3 | `resource.metadata["bid"]["delivery_days"]` | `(delivery_max - delivery_days) / (delivery_max - delivery_min)` |
| 信誉 | 0.2 | `resource.metadata["trust_score"]` | `trust_score / 5.0` |

**归一化基准**：`task.custom_fields["bid_price_range"]=(min,max)` 与 `task.custom_fields["bid_delivery_range"]=(min,max)`

**综合分**：`total = price_score*0.5 + delivery_score*0.3 + trust_normalized*0.2`，`round(..., 6)`

**评分方向**：降序优先（高分优先，配合 `ReverseAuction` 的 `reverse=True`）

### 3.6 `broker.py` — BrokerAgent（虚拟中间人）

```
BrokerAgent
    ├─ server: UMCPServer                    # 持有 server 引用（用于 event_bus）
    ├─ broker_user_id: str = "broker_001"    # 虚拟中间人用户 ID
    ├─ aggregation_threshold: int = 3        # 聚合阈值
    ├─ _buffer: dict[str, list[BuyerTask]]   # 按 category 分桶的缓冲池
    │
    ├─ submit_buyer_task(task: BuyerTask)    # 提交采购需求到缓冲池
    ├─ try_aggregate(category: str) -> TenderTask | None  # 尝试聚合
    └─ notify_buyers(tender, event_type)     # 事件通知
```

**聚合算法**：
```python
total_quantity = sum(t.custom_fields["quantity"] for t in batch)
total_budget = sum(t.custom_fields["quantity"] * t.budget_max for t in batch)
target_unit_price = round(total_budget / total_quantity, 2)  # 按数量加权
```

**子任务构造**：
- 商品子任务 `StandardTask`：`sku="AGG-{category}"`、`quantity=total_quantity`
- 服务子任务 `CustomTask`：`proposal_requirements=["含配送", "含安装"]`

**防重复聚合**：聚合后从缓冲池移除该批 BuyerTask（切片 `pending[threshold:]`）

**独立品类**：不同 category 互不影响，独立缓冲独立聚合

**事件通知**：
```python
def notify_buyers(self, tender: TenderTask, event_type: str) -> None:
    evt_type = EventType(event_type)  # 解析失败时兜底为 EventType.TASK_PUBLISHED
    event = Event(
        type=evt_type,
        source_layer="L2",
        payload={tender_id, category, buyer_task_ids},
    )
    self._server.event_bus.publish(event)
```

### 4.2 与核心库 L3/L4/L5 层的对接

| 核心层 | 核心组件 | 插件中的对接点 |
|--------|---------|---------------|
| L3 匹配 | `ReverseAuction` / `CredentialFilter` / `CompositeBidScorer` | `register_plugin` 实例化 `ReverseAuction`；`TenderBidScorer` 内部组合 `CompositeBidScorer`；filters 要求 `business_license` |
| L4 支付 | `InstallmentPayment` / `FlatCommissionRule` | `register_plugin` 实例化 `InstallmentPayment(deposit_ratio=0.3)` + `FlatCommissionRule(rate=0.05)` |
| L5 信任 | `WeightedSumTrustEngine` / `Evaluation` | `register_plugin` 实例化引擎（4 维度）；准入规则 `trustScore >= 3.0` |
| 事件总线 | `EventBus` / `Event` / `EventType` | `BrokerAgent.notify_buyers()` 通过 `event_bus.publish()` 发布招标通知 |

### 4.3 完整业务流程

```
1. 采购方提交需求（BuyerTask）
   ├─ category="空调", quantity=10, budget_max=3000
   └─ broker.submit_buyer_task(task) → 进入缓冲池

2. BrokerAgent 聚合（阈值=3）
   ├─ 同品类满 3 个 → try_aggregate("空调")
   ├─ 计算 total_quantity=30, target_unit_price=加权平均
   ├─ 创建商品子任务 StandardTask(sku="AGG-空调", quantity=30)
   ├─ 创建服务子任务 CustomTask(proposal_requirements=["含配送","含安装"])
   ├─ 创建 TenderTask(buyer_task_ids=[...], standard_sub_tasks=[商品], custom_sub_task=服务)
   └─ notify_buyers(tender, "task.published") → EventBus 发布事件

3. 供应商投标
   ├─ SupplierResource.metadata["bid"] = {"price": 2800, "delivery_days": 7}
   └─ ReverseAuction + TenderBidScorer 评分：
       ├─ 无 business_license → -1.0（排除）
       ├─ 服务能力不匹配 → -1.0（排除）
       └─ score = price_score*0.5 + delivery_score*0.3 + trust_score*0.2

4. 中标 → TenderTask.assign_to(supplier_id) → ASSIGNED

5. 分期付款（InstallmentPayment）
   ├─ calculate(task, deal) → PaymentOrder
   │   ├─ deposit_amount = total × 30%
   │   ├─ balance_amount = total × 70%
   │   └─ metadata: {deposit_status:"none", balance_status:"none"}
   ├─ hold_deposit(order) → deposit_status="held"
   ├─ capture_deposit(order) → deposit_status="captured"
   └─ capture_balance(order) → balance_status="captured", order.status=CAPTURED

6. 履约
   ├─ 商品子任务 complete()
   ├─ 服务子任务 complete()
   └─ TenderTask.complete()（前置校验所有子任务 COMPLETED）

7. 信任评价（Evaluation）
   └─ WeightedSumTrustEngine.record_evaluation(ratings={delivery:5.0, quality:4.0, ...})
       → 更新 TrustProfile，影响下次准入
```

## 五、InstallmentPayment 订金/尾款流程详解

`InstallmentPayment` 定义在核心库 `umcp_core.layers.l4.transaction`，插件通过 `register_plugin` 注入。

### 5.1 PaymentOrder.metadata 字段

| 字段 | 初始值 | 流转 |
|------|--------|------|
| `deposit_amount` | `round(total × 0.3, 2)` | 不变 |
| `balance_amount` | `round(total × 0.7, 2)` | 不变 |
| `deposit_status` | `"none"` | `none → held → captured` |
| `balance_status` | `"none"` | `none → captured` |

### 5.2 状态流转

```
订金流程：
  hold_deposit(order)    → deposit_status: "none" → "held",  order.status=HELD
  capture_deposit(order) → deposit_status: "held" → "captured"

尾款流程：
  capture_balance(order) → balance_status: "none" → "captured", order.status=CAPTURED
  （前置条件：deposit_status=="captured" 且 balance_status=="none"）

抽象方法委托：
  hold(order)    → hold_deposit(order)
  capture(order) → 自动推进：hold_deposit → capture_deposit → capture_balance
  refund(order)  → order.status=REFUNDED, 两 status 同步置 "refunded"
```


### 7.2 提交采购需求并聚合

```python
from umcp_core.core.domain import DomainTag
from group_buying.tasks import BuyerTask
from group_buying.broker import BrokerAgent

broker = BrokerAgent(server, broker_user_id="broker_001", aggregation_threshold=3)

# 提交 3 个空调采购需求
for i in range(3):
    task = BuyerTask(
        demander_id=f"buyer_{i}",
        domain_tag=DomainTag.of("group_buying"),
        category="空调",
        quantity=10,
        budget_max=3000.0,
        spec_requirements=["1.5匹", "变频"],
    )
    broker.submit_buyer_task(task)

# 聚合生成 TenderTask
tender = broker.try_aggregate("空调")
# tender.custom_fields["total_quantity"] = 30
# tender.custom_fields["target_unit_price"] = 3000.0
# tender.buyer_task_ids = ["buyer_0", "buyer_1", "buyer_2"]
broker.notify_buyers(tender, "task.published")
```

### 7.3 供应商投标

```python
from umcp_core.core.domain import DomainTag
```

### 7.4 匹配与分期付款

```python
from umcp_core.core.deal import Deal

# 匹配
tender.publish()
strategy = server.match_strategy_for("group_buying")
candidates = server.resource_repo.find_available(tender.domain_tag)
result = strategy.execute(tender, candidates)
tender.assign_to(result.selected_resource_id)

# 创建交易
deal = Deal(
    task_id=tender.task_id,
    resource_id=result.selected_resource_id,
    demander_id=tender.demander_id,
    supplier_id="supplier_001",
    final_amount=84000.0,  # 30 台 × 2800 元
)
deal.activate()

# 分期付款
payment_schema = server.payment_schema_for("group_buying")
order = payment_schema.calculate(tender, deal)
# order.metadata["deposit_amount"] = 25200.0  (30%)
# order.metadata["balance_amount"] = 58800.0  (70%)

payment_schema.hold_deposit(order)      # deposit_status: none → held
payment_schema.capture_deposit(order)   # deposit_status: held → captured
payment_schema.capture_balance(order)   # balance_status: none → captured, order.status=CAPTURED
```

## 八、设计要点总结

1. **完整业务闭环**：需求聚合 → 集采招标 → 供应商投标 → 分期付款 → 履约评价，覆盖双边市场全链路
2. **PackageTask 抽象验证**：`TenderTask` 继承 `PackageTask`，支持商品（StandardTask）+ 服务（CustomTask）双子任务，重写 `complete()` 前置校验
3. **BrokerAgent 虚拟中间人**：独立类（非继承），按品类分桶缓冲，阈值聚合，防重复，独立品类互不影响
4. **多维报价评分**：`TenderBidScorer` 组合 `CompositeBidScorer`，行业硬约束（license + 服务标签）+ 通用三维度加权（价格/交期/信誉）
5. **分期付款流程**：`InstallmentPayment` 扩展 `PaymentOrder.metadata`，订金（30%）与尾款（70%）独立流转，支持 `hold_deposit → capture_deposit → capture_balance` 渐进式扣款
6. **事件驱动通知**：`BrokerAgent.notify_buyers()` 通过 `EventBus.publish()` 发布招标通知，复用 `EventType.TASK_PUBLISHED`
7. **零核心库抽象基类修改**：所有扩展通过子类化 `PackageTask` / `CustomTask` / `Resource` 和组合 `CompositeBidScorer` / `InstallmentPayment` 实现
