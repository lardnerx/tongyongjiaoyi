# 多插件并存（阶段四 A）说明文档

**阶段**：四 A（多插件并存）
**适用范围**：`UMCPServer` 同一实例中加载多个行业插件、按 `domain` 路由的机制
**文档定位**:面向核心库使用者和插件开发者，完整说明多插件并存的架构、注册接口、加载机制、domain 路由与使用方法。

---

## 一、概述

### 1.1 阶段目标

阶段四 A 的目标是让多个行业插件（`ride_hailing`、`escort_driving`、`group_buying`）能够在**同一个 `UMCPServer` 实例**中并存，并按 `task.domain_tag` 路由到各自注册的匹配策略、支付模式、信任引擎与准入规则。

### 1.2 解决的问题

在阶段四 A 之前，`UMCPServer` 通过单值属性 `self.match_strategy` / `self.payment_schema` / `self.trust_engine` 持有组件（见 `src/umcp_core/server.py:83-85`），这意味着：

- 同一时刻只能服务一个行业 domain
- 后加载的插件会**覆盖**先加载插件的组件（`set_match_strategy` 直接赋值，见 `server.py:156-157`）
- `RuleEngine` 的准入规则无法按 domain 隔离，ride 行业的 `driver_license` 准入要求会误伤 group_buying 的买家

### 1.3 核心设计

引入**按 domain 注册**的策略注册表，与单值属性并存：

```
UMCPServer
├── _match_strategies: dict[str, MatchStrategy]   # 按 domain 索引
├── _payment_schemas:   dict[str, PaymentSchema]   # 按 domain 索引
├── _trust_engines:     dict[str, TrustEngine]     # 按 domain 索引
├── match_strategy / payment_schema / trust_engine # 单值属性（兜底）
└── rule_engine: RuleEngine
    ├── _domain_access_rules:    dict[str, list[AccessRule]]  # 按 domain 隔离
    ├── _access_rules:           list[AccessRule]             # 全局兜底
    └── _domain_trust_engines:   dict[str, TrustEngine]       # trustScore 路由
```

设计要点：
1. **按 domain 注册**：`register_*(domain, component)` 将组件存入字典，key 统一小写化
2. **单值兜底**：注册时同时更新单值属性（指向最后注册的），未命中 domain 查询时回退
3. **向后兼容**：缺 `domain` 字段的旧插件仍走单值模式，不破坏阶段一/二/三的行为
4. **治理层联动**：`register_trust_engine` 同步到 `RuleEngine`，使 `access_rule` 中的 `trustScore` 能按 domain 路由取值

## 三、核心设计

### 3.1 多插件并存的架构

阶段四 A 采用**双轨制**：字典索引 + 单值兜底，二者并存。

```
                    register_match_strategy("ride", s1)
                    register_match_strategy("group_buying", s2)
                              │
                              ▼
        ┌─────────────────────────────────────────────┐
        │  _match_strategies:                          │
        │    {"ride": s1, "group_buying": s2}          │
        │  match_strategy = s2  (单值，指向最后注册的)   │
        └─────────────────────────────────────────────┘
                              │
            match_strategy_for("ride")         → s1   (字典命中)
            match_strategy_for("unknown")      → s2   (字典未命中，回退单值)
            match_strategy_for(DomainTag.of("RIDE")) → s1 (DomainTag 入参 + 小写化)
```

此设计同样适用于 `_payment_schemas` / `_trust_engines`（见 `server.py:97-99`）。

### 3.2 register 方法

三个 register 方法位于 `src/umcp_core/server.py:175-197`，统一模式：**字典写入 + 单值更新**。

#### `register_match_strategy(domain, strategy)` — `server.py:175-178`

```python
def register_match_strategy(self, domain: str, strategy: MatchStrategy) -> None:
    """按 domain 注册匹配策略，同时更新单值属性作为兜底。"""
    self._match_strategies[domain.lower()] = strategy
    self.match_strategy = strategy
```

#### `register_payment_schema(domain, schema)` — `server.py:180-183`

```python
def register_payment_schema(self, domain: str, schema: PaymentSchema) -> None:
    """按 domain 注册支付模式，同时更新单值属性作为兜底。"""
    self._payment_schemas[domain.lower()] = schema
    self.payment_schema = schema
```

#### `register_trust_engine(domain, engine)` — `server.py:185-197`

`register_trust_engine` 比 match/payment 多一步：**同步到 `RuleEngine`**，使准入规则中的 `trustScore` 能按 domain 路由。

```python
def register_trust_engine(self, domain: str, engine: TrustEngine) -> None:
    key = domain.lower()
    self._trust_engines[key] = engine
    self.trust_engine = engine
    # 同步到 RuleEngine，使 access_rule 的 trustScore 能按 domain 路由
    self.rule_engine.register_trust_engine(key, engine)
```

**设计要点**：
- `domain` 统一 `.lower()` 小写化，与 `DomainTag.of(...).value` 保持一致（见 `server.py:177,182,193`）
- 单值属性指向**最后注册**的组件，作为未命中 domain 时的兜底（见 `server.py:178,183,195`）
- `register_trust_engine` 额外调用 `self.rule_engine.register_trust_engine`（见 `server.py:197`），这是治理层联动的关键

### 3.3 查询方法

三个查询方法位于 `src/umcp_core/server.py:199-212`，统一模式：**字典查询 + 单值兜底**。

#### `match_strategy_for(domain)` — `server.py:199-202`

```python
def match_strategy_for(self, domain: DomainTag | str) -> MatchStrategy | None:
    """按 domain 查询匹配策略，未命中时回退到单值属性。"""
    key = domain.value if isinstance(domain, DomainTag) else str(domain).lower()
    return self._match_strategies.get(key, self.match_strategy)
```

#### `payment_schema_for(domain)` — `server.py:204-207`

```python
def payment_schema_for(self, domain: DomainTag | str) -> PaymentSchema | None:
    key = domain.value if isinstance(domain, DomainTag) else str(domain).lower()
    return self._payment_schemas.get(key, self.payment_schema)
```

#### `trust_engine_for(domain)` — `server.py:209-212`

```python
def trust_engine_for(self, domain: DomainTag | str) -> TrustEngine | None:
    key = domain.value if isinstance(domain, DomainTag) else str(domain).lower()
    return self._trust_engines.get(key, self.trust_engine)
```

**设计要点**：
- 入参既支持 `DomainTag` 也支持 `str`（见 `server.py:199` 的 `DomainTag | str` 类型注解）
- 若传入 `DomainTag`，取其 `.value`（已经是小写字符串，由 `DomainTag.of()` 保证）
- 若传入 `str`，统一 `.lower()` 后查询
- 字典未命中时回退到单值属性（`self.match_strategy` / `self.payment_schema` / `self.trust_engine`）

### 3.4 字典索引

三个字典在 `UMCPServer.__init__` 中初始化（见 `server.py:96-99`）：

```python
# 按 domain 索引的策略注册表（多插件并存支持）
self._match_strategies: dict[str, MatchStrategy] = {}
self._payment_schemas: dict[str, PaymentSchema] = {}
self._trust_engines: dict[str, TrustEngine] = {}
```

此外还有两个相关字典：
- `_subtask_executors: dict[str, Any]`（`server.py:105`）：按 domain 注册复合任务的子任务执行器，覆盖默认 `_execute_subtask_by_domain` 行为
- `_domain_trust_engines: dict[str, TrustEngine]`（`governance.py:199`）：`RuleEngine` 内部维护，供 `RuleContext.trust_score` 路由

### 3.5 单值属性兜底机制

单值属性在 `__init__` 中初始化为 `None`（见 `server.py:83-85`）：

```python
self.match_strategy: MatchStrategy | None = None
self.payment_schema: PaymentSchema | None = None
self.trust_engine: TrustEngine | None = None
```

**兜底语义**：
1. `register_*(domain, component)` 时，单值属性被更新为该 component（指向最后注册的）
2. `*_for(domain)` 字典未命中时，返回单值属性
3. `set_*(component)`（旧接口，`server.py:156-163`）只更新单值属性，**不**写入字典——用于阶段一/二/三的向后兼容
4. `_validate_required_components()`（`server.py:467-482`）检查单值属性非 None，作为启动前置条件

**兜底场景示例**：
- 旧插件 manifest 缺 `domain` 字段 → 走单值模式（见 `server.py:329-331`）
- 查询未注册的 domain → 回退到单值（见 `server.py:202,207,212` 的 `.get(key, self.xxx)`）

### 3.6 跨 domain 信任聚合

`UMCPServer` 额外提供跨 domain 的信任聚合能力（见 `server.py:218-224`）：

```python
def aggregate_trust_score(self, user_id: str) -> float:
    """跨 domain 聚合 trust_score。"""
    return self._trust_aggregator.aggregate(user_id, self._trust_engines)
```

默认使用 `MeanTrustAggregator`（算术平均，`server.py:102`），可通过 `set_trust_aggregator`（`server.py:214-216`）替换为自定义聚合策略。

## 四、插件加载机制

### 4.1 `load_plugin()` 三种路径

`load_plugin` 位于 `src/umcp_core/server.py:238-266`，支持三种入参形式：

```python
def load_plugin(self, plugin_path: str | Path) -> PluginDescriptor:
    path = Path(plugin_path)
    if path.is_dir():
        manifest_path = path / "plugin.json"           # 路径 1：目录
    elif path.is_file() and path.suffix == ".json":
        manifest_path = path                            # 路径 2：json 文件
    elif isinstance(plugin_path, str) and "/" not in plugin_path and "\\" not in plugin_path:
        return self._load_plugin_module(plugin_path)   # 路径 3：Python 模块名
    else:
        raise FileNotFoundError(f"无法定位插件: {plugin_path}")
```

| 路径 | 入参示例 | 处理方式 |
|------|---------|---------|
| 目录 | `"plugins/ride_hailing"` | 拼接 `plugin.json` 后读取 |
| json 文件 | `"plugins/ride_hailing/plugin.json"` | 直接读取 |
| 模块名 | `"ride_hailing"` | 调用 `_load_plugin_module`，import 模块后读 `PLUGIN_MANIFEST` |

### 4.2 模块名加载：`_load_plugin_module`

`_load_plugin_module` 位于 `server.py:268-284`：

```python
def _load_plugin_module(self, module_name: str) -> PluginDescriptor:
    module = importlib.import_module(module_name)
    if not hasattr(module, "PLUGIN_MANIFEST"):
        raise AttributeError(f"插件模块 {module_name} 缺少 PLUGIN_MANIFEST")
    manifest = getattr(module, "PLUGIN_MANIFEST")
    descriptor = PluginDescriptor(manifest, Path(module_name))
    self._apply_manifest(descriptor)
    # 允许插件模块自定义初始化钩子
    if hasattr(module, "register_plugin"):
        getattr(module, "register_plugin")(self)
    self._plugins.append(descriptor)
    return descriptor
```

**关键步骤**：
1. `importlib.import_module` 导入插件包
2. 读取模块级 `PLUGIN_MANIFEST` 字典（与 `plugin.json` 内容一致）
3. 调用 `_apply_manifest` 处理声明式字段（task_types / match_strategy / payment_schema / trust_engine / access_rule）
4. **若模块定义了 `register_plugin(server)` 钩子，调用它**——这是插件注入"需要构造参数的组件"的入口（如带 scorer 和 filter 的 `InstantMatch`）

### 4.3 `_apply_manifest()` 反射加载

`_apply_manifest` 位于 `server.py:286-342`，是声明式清单的解析核心。

#### 4.3.1 domain 解析（`server.py:291-298`）

```python
domain_field = manifest.get("domain")
if domain_field is None:
    domains: list[str] = []                    # 无 domain → 单值模式
elif isinstance(domain_field, str):
    domains = [domain_field.lower()]           # 单 domain
else:
    domains = [str(d).lower() for d in domain_field]  # domain 列表（跨域插件）
```

支持三种形态：
- `None`：缺 `domain` 字段，`domains=[]`，仅更新单值属性（向后兼容）
- `"ride"`：单 domain 字符串
- `["ride", "escort"]`：domain 列表，跨域插件会注册到多个 domain

#### 4.3.2 task_types 注册（`server.py:301-304`）

```python
for task_type_path in manifest.get("task_types", []):
    cls = _import_class(task_type_path)
    type_name = getattr(cls, "_task_type_name", cls.__name__.lower())
    self.task_factory.register_builder(type_name, cls)
```

通过点分路径反射导入任务类，取 `_task_type_name` 属性（或类名小写）作为工厂 key。

#### 4.3.3 match_strategy 注入（`server.py:307-312`）

```python
if "match_strategy" in manifest:
    cls = _import_class(manifest["match_strategy"])
    instance = cls()
    self.match_strategy = instance              # 单值兜底
    for d in domains:
        self._match_strategies[d] = instance    # 按 domain 注册
```

**注意**：`_apply_manifest` 用 `cls()` 无参构造，因此 manifest 中的 `match_strategy` 只能是**无构造参数**的类。需要 scorer / filter 等参数的策略（如带 `RideMatchScorer` 的 `InstantMatch`）必须通过 `register_plugin` 钩子注入（见 4.2）。

#### 4.3.4 payment_schema 注入（`server.py:315-320`）

```python
if "payment_schema" in manifest:
    cls = _import_class(manifest["payment_schema"])
    instance = cls()
    self.payment_schema = instance
    for d in domains:
        self._payment_schemas[d] = instance
```

同理，需要构造参数的支付模式（如 `DynamicPricing(surge_factor=1.0, ...)`、`InstallmentPayment(deposit_ratio=0.3, ...)`）由 `register_plugin` 钩子注入。

#### 4.3.5 trust_engine 注入（`server.py:323-331`）

```python
if "trust_engine" in manifest:
    cls = _import_class(manifest["trust_engine"])
    instance = cls()
    if domains:
        for d in domains:
            self.register_trust_engine(d, instance)   # 走 register，同步到 RuleEngine
    else:
        # 无 domain 时仅更新单值属性（保持原行为）
        self.trust_engine = instance
```

**关键差异**：trust_engine 通过 `register_trust_engine` 注册（而非直接写字典），确保同步到 `RuleEngine._domain_trust_engines`。

#### 4.3.6 access_rule 配置（`server.py:334-342`）

```python
if "access_rule_expression" in manifest:
    from umcp_core.layers.l7 import ExpressionAccessRule
    rule = ExpressionAccessRule(manifest["access_rule_expression"])
    if domains:
        for d in domains:
            self.rule_engine.add_access_rule(rule, domain=d)   # 按 domain 注册
    else:
        self.rule_engine.add_access_rule(rule)                  # 全局生效
```

准入规则通过 `RuleEngine.add_access_rule(rule, domain=d)` 按 domain 隔离注册（见第五章）。

### 4.5 `register_plugin` 钩子：声明式 + 命令式分工

以 `ride_hailing/__init__.py:30-58` 为例：

```python
def register_plugin(server: "UMCPServer") -> None:
    domain = PLUGIN_MANIFEST["domain"]
    from umcp_core.layers.l3 import CredentialFilter, InstantMatch
    from umcp_core.layers.l4 import DynamicPricing, FlatCommissionRule
    from umcp_core.layers.l5 import WeightedSumTrustEngine
    from ride_hailing.scoring import RideMatchScorer

    server.register_match_strategy(
        domain,
        InstantMatch(
            scorer=RideMatchScorer(),                                    # 需要 scorer
            filters=[CredentialFilter(required_credentials=["driver_license"])],  # 需要 filter
        ),
    )
    server.register_payment_schema(
        domain,
        DynamicPricing(
            surge_factor=1.0,
            commission_rule=FlatCommissionRule(rate=PLUGIN_MANIFEST["commission_rate"]),
        ),
    )
    server.register_trust_engine(
        domain,
        WeightedSumTrustEngine(dimensions=PLUGIN_MANIFEST["trust_dimensions"]),
    )
```

**分工原则**：
- `plugin.json` + `_apply_manifest`：处理**无构造参数**的声明式字段（task_types、access_rule_expression，以及无参的 match_strategy 类路径）
- `register_plugin` 钩子：处理**需要构造参数**的组件（带 scorer/filter 的策略、带 rate/deposit_ratio 的支付模式、带 dimensions 的信任引擎）

三个插件的 `register_plugin` 钩子统一通过 `register_*` 方法注入，因此**自动**写入 domain 字典并同步单值属性与 RuleEngine。

## 五、多 domain 路由

### 5.1 `task.domain_tag` 驱动路由

`Task` 携带 `domain_tag: DomainTag` 字段，`DomainTag.of(value)` 将 value 小写化存储。多插件并存的查询入口都以 `task.domain_tag.value` 为路由 key：

| 调用点 | 路由方式 | 代码位置 |
|--------|---------|---------|
| `server.match_strategy_for(domain)` | 字典查询 + 单值兜底 | `server.py:199-202` |
| `server.payment_schema_for(domain)` | 字典查询 + 单值兜底 | `server.py:204-207` |
| `server.trust_engine_for(domain)` | 字典查询 + 单值兜底 | `server.py:209-212` |
| `server._execute_subtask_by_domain(subtask)` | `subtask.domain_tag.value` → `_subtask_executors` 或 `match_strategy_for` | `server.py:412-437` |
| `rule_engine.check_access(user, task)` | `task.domain_tag.value` → domain 规则 + 全局规则 | `governance.py:227-242` |

复合任务的子任务派发也按 domain 路由（`server.py:412-437`）：

```python
def _execute_subtask_by_domain(self, subtask: Task) -> None:
    domain = subtask.domain_tag.value
    custom_executor = self._subtask_executors.get(domain)
    if custom_executor is not None:
        custom_executor(subtask)
        return
    strategy = self.match_strategy_for(domain)
    if strategy is None:
        raise RuntimeError(f"domain {domain} 未注册匹配策略")
    ...
```

### 5.2 `RuleEngine` 按 domain 注册 access_rule

`RuleEngine` 位于 `src/umcp_core/layers/l7/governance.py:185-251`，维护两套规则存储（`governance.py:196-197`）：

```python
self._access_rules: list[AccessRule] = []                    # 全局兜底
self._domain_access_rules: dict[str, list[AccessRule]] = {}  # 按 domain
```

#### `add_access_rule(rule, domain=None)` — `governance.py:203-212`

```python
def add_access_rule(self, rule: AccessRule, domain: str | None = None) -> None:
    if domain is None:
        self._access_rules.append(rule)                      # 全局规则
    else:
        self._domain_access_rules.setdefault(domain, []).append(rule)  # domain 隔离
```

#### `check_access(user, task)` — `governance.py:227-242`

```python
def check_access(self, user: User, task: Task) -> bool:
    domain = task.domain_tag.value
    rules = self._domain_access_rules.get(domain, []) + self._access_rules
    # 注入 domain→engine 路由能力到 ExpressionAccessRule（仅一次，幂等）
    for rule in rules:
        if isinstance(rule, ExpressionAccessRule) and rule._trust_engine_lookup is None:
            rule.bind_trust_engine_lookup(
                lambda d: self._domain_trust_engines.get(d)
            )
    return all(rule.check(user, task) for rule in rules)
```

**路由顺序**：先校验 task 对应 domain 的规则，再校验全局规则，任一不通过则拒绝（`all(...)` 语义）。

**隔离示例**（对应 `test_access_rule_does_not_leak_across_domains`）：
- ride domain 注册 `hasCredential('driver_license')` 规则
- group_buying domain 注册 `hasCredential('business_license')` 规则
- 用户只有 `business_license`：ride task 被拒（缺 driver_license），group_buying task 通过
- 两个 domain 的规则互不泄漏

### 5.3 `TrustEngine` 按 domain 注册并同步到 `RuleEngine`

准入规则表达式中的 `trustScore` 需要按 domain 路由到对应 TrustEngine 取值，这通过三层联动实现：

#### 第一层：`server.register_trust_engine` 同步（`server.py:185-197`）

```python
def register_trust_engine(self, domain: str, engine: TrustEngine) -> None:
    key = domain.lower()
    self._trust_engines[key] = engine
    self.trust_engine = engine
    self.rule_engine.register_trust_engine(key, engine)   # 同步到 RuleEngine
```

#### 第二层：`RuleEngine.register_trust_engine` 存储（`governance.py:214-219`）

```python
def register_trust_engine(self, domain: str, engine: TrustEngine) -> None:
    self._domain_trust_engines[domain.lower()] = engine
```

#### 第三层：`check_access` 注入路由能力 + `RuleContext.trust_score` 路由

`check_access` 在求值前向 `ExpressionAccessRule` 注入 `domain → TrustEngine` 的查询回调（`governance.py:237-241`，幂等仅注入一次）：

```python
for rule in rules:
    if isinstance(rule, ExpressionAccessRule) and rule._trust_engine_lookup is None:
        rule.bind_trust_engine_lookup(
            lambda d: self._domain_trust_engines.get(d)
        )
```

`RuleContext.trust_score` 属性（`governance.py:140-152`）使用该回调按 `task.domain_tag` 路由：

```python
@property
def trust_score(self) -> float:
    if self.trust_engine_for_domain is not None:
        engine = self.trust_engine_for_domain(self.task.domain_tag.value)
        if engine is not None:
            return engine.evaluate(self.user.user_id).overall_score
    return float(self.user.metadata.get("trust_score", 0.0))  # 向后兼容
```

**路由效果**：
- ride task 的 `trustScore` 走 ride 的 `WeightedSumTrustEngine`（4 维：punctuality/cleanliness/...）
- group_buying task 的 `trustScore` 走 group_buying 的 `WeightedSumTrustEngine`（4 维：delivery/quality/...）
- 同一用户在两个 domain 的信任分**独立计算**，互不影响
- 未注入回调时回退到 `user.metadata['trust_score']`，向后兼容阶段一/二/三

#### `ExpressionAccessRule.bind_trust_engine_lookup` 幂等性（`governance.py:39-47`）

```python
def bind_trust_engine_lookup(self, lookup: Callable[[str], TrustEngine | None]) -> None:
    if self._trust_engine_lookup is None:
        self._trust_engine_lookup = lookup   # 仅当未绑定时注入
```

幂等设计避免重复 check_access 时反复覆盖闭包，保证 `lambda d: self._domain_trust_engines.get(d)` 始终引用当前 `RuleEngine` 的最新字典。

## 八、设计要点总结

1. **双轨制架构**：字典索引（`_match_strategies` / `_payment_schemas` / `_trust_engines`）+ 单值兜底（`self.match_strategy` 等），既支持多 domain 路由又向后兼容单插件场景
2. **统一小写化**：所有 domain key 经 `.lower()` 处理，与 `DomainTag.of(...).value` 保持一致，避免大小写不匹配
3. **register 同步单值**：`register_*` 方法同时更新字典与单值属性，单值指向最后注册的，作为未命中 domain 的兜底
4. **治理层联动**：`register_trust_engine` 同步到 `RuleEngine._domain_trust_engines`，`check_access` 注入 `domain → TrustEngine` 路由能力，使 `trustScore` 表达式按 task domain 取值
5. **准入规则隔离**：`RuleEngine` 用 `_domain_access_rules`（按 domain）+ `_access_rules`（全局）双存储，domain 规则只对该 domain task 生效，全局规则对所有 task 生效
6. **声明式 + 命令式分工**：`plugin.json` + `_apply_manifest` 处理无参组件，`register_plugin` 钩子处理需要构造参数的组件（带 scorer/filter 的策略、带 rate 的支付模式、带 dimensions 的信任引擎）
7. **幂等注入**：`ExpressionAccessRule.bind_trust_engine_lookup` 仅当未绑定时注入，避免重复 check_access 覆盖闭包
8. **零抽象基类修改**：多插件并存能力完全通过 `UMCPServer` 新增字典字段与 `RuleEngine` 新增 domain 存储实现，不修改 `Task` / `Resource` / `MatchStrategy` 等抽象基类
